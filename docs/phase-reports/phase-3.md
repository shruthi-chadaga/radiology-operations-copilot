# Phase 3 — Authored report workflow

## Status

Phase 3 is implemented as a synthetic, user-authored report slice in the Imaging Workspace. It does not interpret images, generate diagnoses, or claim clinical authority.

## Delivered

- Persisted `radiology_reports` workflow records keyed to a PACS study.
- Append-only `radiology_report_versions` records containing authored indication, findings, and impression text.
- Draft save, finalize, and correction-version state transitions.
- Finalized versions are immutable; corrections append a new version and require a reason.
- Imaging worklist report status updates to draft/finalized states without mutating Scheduling Automation records.
- Protected report APIs for imaging operator roles (`pacs_admin`, `operations_manager`). Auditors can read report history but cannot author or finalize.
- Audit events for draft save, finalization, and correction creation.
- Frontend report workspace with explicit authored-text and synthetic-only messaging.

## API surface

- `GET /api/v1/imaging/studies/{study_id}/report`
- `POST /api/v1/imaging/studies/{study_id}/report/draft`
- `POST /api/v1/imaging/reports/{report_id}/finalize`
- `POST /api/v1/imaging/reports/{report_id}/correction`

## Boundaries and risks

- Only PACS studies with `metadata_json.synthetic == true` may be reported.
- Report text is not generated by an AI model and no diagnostic interpretation is performed.
- This is not an EHR/FHIR DiagnosticReport export and has no patient-email or print workflow yet.
- Production deployment would need stronger identity, signing policy, concurrency handling, retention controls, and clinical governance.

## Next slice

Add controlled sharing/export adapters, synthetic patient delivery, print/PDF, and mock EHR export only after the report workflow receives API-level authorization and full-stack verification.
